# Parametric Interface 2 — lyric spreadsheet

Route: `/parametric-interface/2`

## Trial contract

- **Participant situation:** a viewer encounters a single spreadsheet-sized
  field.
- **Primary parameter:** lyric-word timing. Each word holds for its authored
  190–760 ms duration. Every word boundary produces a new operational-data
  snapshot across every non-lyric cell. Reduced-motion preference holds the
  current word and operational-data snapshot.
- **Perceptual job:** notice that the lyric words occupy ordinary cells in the
  fixed centre row while their values change, against a continuously renewed
  working-data field.
- **Interaction job:** none in this display-only trial.
- **Wrapper justification:** the lyric is a changing value inside a real
  spreadsheet grammar: frozen headers, cell selection, sheet tabs, and an
  ordinary rectangular grid. Each word remains in its own unmerged centre-row
  cell, and the active-cell selection follows the current word exactly.
- **System family:** the browser viewport is the spreadsheet application with
  no outer page margin; the parameter changes cell contents, not the wrapper.
- **Removal test:** remove the word values and the result remains an ordinary
  spreadsheet. No lyric text sits above, beside, or outside of cells.

## Preserved invariants

- one non-scrollable browser viewport, with the spreadsheet filling it edge to
  edge;
- no external controls or app navigation inside the work;
- only the supplied original lyric text is rendered;
- `prefers-reduced-motion` freezes the lyric cue;
- lyrics are only rendered inside individual, unmerged table cells.

## Open question

Does continuously renewed surrounding work data make the lyric's word-level
