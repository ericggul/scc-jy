# Parametric Interface 6 — terminal line

Route: `/parametric-interface/6`

## Trial contract

- **Participant situation:** a viewer encounters one edge-to-edge, read-only
  macOS-style zsh session.
- **Primary parameter:** the audio-timed onset of each lyric word. A word is
  appended to the live `printf` argument at its authored song position; at the
  next cue, the completed command settles into ordinary shell scrollback with
  its standard output.
- **Perceptual job:** notice a line being composed as a terminal command, then
  recognise the completed lyric as the result of that command. The sentence
  grows inside the shell's active input row rather than appearing as a display
  layer.
- **Interaction job:** none. This is a self-writing terminal transcript, not
  a simulated command prompt for audience input.
- **Wrapper justification:** a command-line interface treats an in-progress
  command as a single mutable semantic slot. A quoted `printf` argument makes
  the lyric's word-by-word accumulation an ordinary, legible operation of
  that grammar; command/output pairs retain the completed trace.
- **System family:** the terminal fills the viewport and keeps the necessary
  application chrome, monospaced line rhythm, prompt, scrollback, standard
  output, and cursor. No lyric is placed in a title, overlay, badge, or
  separate text treatment.
- **Removal test:** removing the `printf` arguments leaves a coherent terminal
  transcript. Removing the terminal's prompt, command rows, output rows, and
  cursor leaves no independent lyric presentation.

## Rejected excursion

A multi-window terminal-field variation was rejected. It made window count,
z-order, grid placement, and replacement behavior more prominent than the
terminal line itself; its type became too small, and it read as generic AI
desktop decoration. The retained `/6` relation is one terminal, one evolving
command-line argument, and ordinary command/output scrollback.
