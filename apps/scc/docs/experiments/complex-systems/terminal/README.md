# Terminal colony experiment

Route: `/terminal/1`, owned by the filesystem-only `complex-systems` group.

Date: 2026-08-13.

## Interface premise

1. **Participant situation:** a person observes a collection of terminal shells that are writing to themselves and one another. They may pause the field or release an unaddressed fragment into the shared environment.
2. **Primary parameter:** each shell's locally timed decision to scan, inspect, send, listen, or fork a child shell.
3. **Perceptual job:** notice that commands begin at different moments, travel only to named peers, and occasionally open a new terminal without a global sequence.
4. **Interaction job:** release one fragment without choosing its recipient, then see which terminals independently inspect, retain, or transmit it. Pause freezes the observed state; neither action commands an agent.
5. **Wrapper justification:** terminal text is the material action of the experiment. A prompt makes an agent's otherwise invisible decision legible as a concrete command and response, while a flexible field lets a new shell visibly take up space.
6. **System family:** the complex-systems full-viewport grammar, serif title, monospaced operational text, restrained mineral ground, and small functional controls are retained. The dark terminal surface is justified by the command grammar, not used as generic technical decoration.
7. **Removal test:** the shell grid, local command traces, lineage labels, fragment release, and pause remain. Titles, generated IDs, charts, connection badges, terminal window decoration, timestamps, and progress metrics have been omitted.

## Bounded trial

- **Baseline:** the SCC complex-systems one-screen field and its direct local-rule simulations.
- **Changed variable:** spatial nodes become terminal shells. Each agent has its own phase, attention, peer list, short command memory, and one-child reproduction limit; commands are the visible system behavior.
- **Retained invariants:** a pure model layer, stable agent and line IDs, a browser-only animation loop, minimal controls, no sockets, and no dashboard representation of the state.
- **No central controller:** the shared tick only advances simulation time, settles already-started commands, and delivers explicitly addressed signals. Each eligible agent evaluates only its own state, known peers, received signals, and the optional shared fragment. The model has no scheduler that selects a colony-wide command or recipient. The generation and one-child limits are bounded material constraints for the experiment, not a coordinating agent.
- **Observable result:** not yet browser-observed in this implementation pass.
- **Unresolved question:** whether a later route should remove the one-child constraint and instead make new-shell survival depend on a locally scarce fragment.
