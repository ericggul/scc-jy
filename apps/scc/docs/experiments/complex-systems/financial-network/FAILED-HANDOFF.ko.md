# 금융 네트워크 실험 — 실패 인계

2026-09-10. 사용자가 **명백한 실패**로 판정하고 작업 중단을 지시했다. 현재 요청은 이 문서 작성뿐이다. 새 지시 없이 구현·조사·테스트를 재개하지 않는다. 기존 코드는 승인된 완성본이나 재사용해야 할 디자인 기준이 아니다.

## 사용자가 실제로 원한 것

핵심은 **현대 자본주의의 차환·돌려막기와 상호의존적 금융 네트워크가, 외부 충격을 계기로 갑작스러운 창발적 붕괴를 일으키는 구조**를 직접 보고 조작하는 실험이다. 개별 실업률이나 특정 영상 주장 검증보다 경제 전체를 복잡계로 조망하려 했다. 탈레브·동역학·네트워크 관점의 추상적이고 예술적인 표현이되, 경제적 관계와 작동 규칙은 납득 가능해야 했다. ‘현대 경제가 정말 돌려막기인가’라는 용어 논쟁으로 요구를 바꾸면 안 된다.

- 5–6개 경제주체 **종류**로 시작하되, 종류마다 여러 노드를 둔다. 가계·기업·은행 등을 한 노드씩으로 축약하지 않는다. 확장 가능해야 한다.
- 직장인은 가계의 고용관계로 표현한다. 같은 기업의 가계들이 같은 고용 충격에 노출된다.
- 완전연결 거미줄 대신 지역적 묶음이 은행·공통 자산 등을 통해 얽힌다.
- 엣지는 실제로 의미 있는 고용·지급·채무·차환·담보 등의 관계다. 방향·종류·금액·규모를 읽을 수 있어야 한다. 채무 잔액과 실제 지급을 혼동하지 않는다.
- 외부 충격이 없으면 지급과 차환이 반복 성공하고, 약한 주기성을 가지면서 계속 작동한다. 시간이 지나면 자동으로 붕괴하도록 만들지 않는다.
- 짧고 작은 단일 충격은 흡수할 수 있다. 여러 위치에 겹치거나 지속되는 충격은 지급·차환·담보 경로를 통해 다른 주체와 전체 경제로 퍼질 수 있다.
- 붕괴는 선택 개수나 미리 정한 애니메이션으로 발생하면 안 된다. 위치·강도·기간·중첩과 실제 상태가 결과를 결정해야 한다.
- 사용자의 조작 → 해당 주체의 변화 → 상대방에 전달되는 변화 → 회복 또는 연쇄 손상이 **직접 지각 가능**해야 한다.

승인받았던 초기 구성은 가계20·기업10·은행4·투자기관4·정부1·중앙은행1, 약40노드였다. 이것은 합성 경제의 구현 제안이며 실측 데이터가 아니다. ‘안장점’이라는 표현은 취약한 정상 운영 상태를 설명하는 직관이었고, 정확한 수학적 안장점을 입증하라는 요구가 아니었다.

## 시각·상호작용 요구

사용자는 정제된 디자인, 최소한의 불필요한 텍스트와 지표, 타당한 알고리즘과 상호작용을 요구했다. **은행인지 가계인지 알려주는 이름, 채무의 방향과 액수까지 없애라는 뜻이 아니다.**

`attractor/3`, `page-rank`, `chess/3`은 레포에 축적된 여러 표현 방식의 예시였다. 한두 예시의 외형을 복사하라는 요청이 아니다. 여러 G(V,E) 실험을 비교하여 정체성·관계·수치·규칙·조작의 결과를 어떻게 지각시키는지 고찰하고, 금융 시스템에 적합한 표현을 설계하라는 요청이었다.

사용자가 구체적으로 지적한 실패:

1. 무엇이 은행·가계·기업인지 알 수 없다.
2. 선과 입자만으로 누가 누구에게 어떤 채무가 있는지 알 수 없다.
3. 중앙은행의 연결이 기본 화면에 보이지 않는다.
4. 각 화살표의 의미, 돈의 규모와 액수가 보이지 않는다.
5. 움직이는 공의 의미가 직관적이지 않다.
6. 네트워크 배치와 스타일이 금융 구조를 설명하지 못하고, 사용자의 미감에도 부합하지 않는다.
7. 어떤 인터랙션이 어떤 변화를 만들고 어떻게 파급되는지 반영하지 못했다.
8. 많은 토큰과 시간을 쓰면서 요청의 핵심보다 불필요한 검증과 작업량을 늘렸다.

## 왜 실패했는가 — 주 에이전트의 책임

**표현할 금융 관계와 사용자의 지각·행동을 먼저 설계하지 않고, 구현하기 편한 화면을 먼저 선택했다.**

- 처음에는 금융 주체를 익명 입자 응집체로, 관계를 미세한 선과 이동 입자로 치환했다. 경제적 정체성과 채무 의미가 사라졌는데도 밀도감과 분위기를 설계의 성과로 취급했다.
- 최소한의 텍스트를 필요한 의미까지 숨기는 것으로 잘못 적용했다. hover 정보만으로 핵심을 보충하려 했다.
- 사용자가 예시를 추가해도 조사 범위를 해당 파일명으로 좁히거나 표면적 형식으로 옮겼다. 예시를 제시한 근본적인 이유를 이해하지 못했다.
- 후속 수정도 이름 추가, 열 배치, 화살표 추가, 색 변경, 모드 분리 등 개별 증상에 대응했다. ‘이 화면에서 경제의 순환과 조작의 파급을 어떻게 이해하는가’라는 전체 설계를 해결하지 못했다.
- 클릭을 모델의 동결 값에 연결한 것만으로 인터랙션을 구현했다고 여겼다. 즉각적인 조작 피드백, 버퍼 때문에 생기는 지연, 이후 상대방의 지급 차질을 연결해 보여주지 못했다.
- 모델 테스트와 타입 검사를 사용자 요구의 충족과 혼동했다. 한때 장기 테스트는 부도 유무만 검사하여 개별 가계 잔액의 누적 불균형도 놓쳤다. 이후 수정했지만 초기 감독 실패를 없애지는 않는다.
- 서브에이전트에게 저비용의 독립 작업을 맡기고 주 에이전트가 의미·설계·통합을 감독하라는 요구가 있었다. 위임은 했지만, 불완전한 산출물을 충분히 걸러내지 못했고 수정 지시를 반복하며 비용을 늘렸다.
- 사용자 승인 없이 임의로 범위를 바꾸거나, 코드가 존재한다는 이유로 의도를 달성했다고 판단했다. 사용자 설명 부족이나 미감의 변덕이 원인이 아니다.

사용자는 반복된 실패 끝에 Astra/GPT에 대한 신뢰를 잃었다고 명시했다. 다음 에이전트는 이 상태를 성공·완료·승인된 방향으로 설명하지 않는다.
