# page-rank

Routes: `/page-rank/1`, `/page-rank/2`. `/page-rank/1` date: 2026-08-20.

## page-rank/1

1. **Participant situation:** a participant encounters the directed graph itself, can let it iterate continuously or one step at a time, and can watch coloured random surfers cross its links while dragging pages only changes spatial arrangement.
2. **Primary parameter:** page rank. Each page is the NetLogo circle whose size follows `0.2 + 4 * sqrt(rank / total-rank)`; the optional adjacent label uses the source model's three-decimal rank value.
3. **Perceptual job:** make the rank distribution's settling visible across one dense directed graph. In random-surfer mode, coloured triangle surfers immediately move to their selected next page while a travelled directed link takes the last traversing surfer's colour for that tick, following the supplied NetLogo `move-to current-page` and `watch-surfers?` branches.
4. **Interaction job:** the lower work surface groups rank calculation, running, graph construction, and display controls. The untouched default is a 150-page / 296-link graph in random-surfer mode with surfer watching enabled; a separate action constructs a 160-page / 471-link extension. Dragging changes only browser-side layout coordinates.
5. **Wrapper justification:** PageRank's graph remains the whole visual field. The lower field-control grammar is retained, but its function groups make the scope of each operation legible: calculation changes the rank process, run changes time, new graph changes topology, and display changes only the rendering.
6. **System family:** this route intentionally does not inherit another `complex-systems` visual grammar. Its white patch field, blue circle pages, black rank labels, and curved grey directed links preserve the supplied NetLogo representation rather than assigning it a new visual identity.
7. **Removal test:** removing page size hides rank; removing rank labels removes the numerical reading; removing a curved arrow removes a directed graph relation; every remaining bottom-bar item changes or reports an actual model variable.

## Bounded trial

- **Baseline:** the supplied NetLogo PageRank model, including its preferential graph generator, damping factor, dangling-page handling, synchronous diffusion update, visit-based random-surfer alternative, `circle` page shape, three-decimal labels, curved links, and 300 spring-layout repetitions.
- **Changed variable:** the runnable browser field retains the source model's graph representation while reorganizing the lower controls by the operation they perform. The small lower work surface keeps direct ranges and actions, but separates rank calculation, running, graph construction, and display; `follow links` describes damping through its visible effect, and graph settings explicitly require a build action. Small static examples were removed; a seeded 150-page / 296-link construction remains the default, alongside an opt-in 160-page / 471-link extension with a broader spring-layout calibration.
- **Invariants:** diffusion distributes every dangling page's rank uniformly before applying teleportation; diffusion rank remains normalized; the surfer method increments a current-page visit before choosing a link-or-teleport move; each surfer retains its identity and colour across updates; every directed link remains a `G(V, E)` relation independent of screen position.
- **Verification target:** unit tests cover the 150-page / 296-link default budget, normalized diffusion with dangling pages, reproducible normalized surfer estimates, seeded preferential generation without self-links or duplicated directed edges, and bounded deterministic spring layout. Topology-derived outgoing links and render lookup tables are cached until topology or page positions change; the 150-page default redraw is capped at 30 fps, while simulation steps continue at the selected rate. Type checking covers the route and interaction layer.
- **Unresolved question:** a later route can isolate personalized teleport vectors or compare convergence error against an analytic stationary distribution while preserving this route as the graph-first baseline.

## page-rank/2

1. **Participant situation:** the same graph can be watched as a network whose relationships slowly respond to its own recent traffic. A darker, thicker directed line has carried more recent flow; when a weak relationship is replaced, its old line leaves in pale coral while the new line enters blue-grey before joining the traffic field.
2. **Changed relation:** `/2` forks `/1` and retains ordinary PageRank transitions. Traffic history does not weight the PageRank calculation; it only governs occasional topology updates. Every 14 simulation steps, the active link setting replaces one to eight weak links; the default is eight. The default rate is 28 steps per second, so the topology updates every half-second.
3. **Replacement rule:** an old link is more likely to be replaced when it has carried little recent traffic and points to a lower-ranked page. Its source keeps the same number of outgoing links. A replacement target is selected from unconnected pages using current rank and accumulated incoming traffic, with a 12% exploration floor. New links are protected for 72 steps so they can be tested before removal. In surfer mode, the rank estimate has a fast fading recent-visit memory rather than an all-time average, allowing individual page size to rise and fall with the rewiring. Eighteen surfers are sampled visibly from the larger calculation ensemble so movement stays legible instead of becoming a blanket of markers.
4. **Interaction job:** the new `links` group is deliberately one short control: `adapt on/off` stops or resumes topology updates; `replace / cycle` sets their quantity. To make the changed relation primary, `/2` starts with rank labels and individual surfers hidden; both remain available under `display`. All rank, run, graph, and display controls remain local to their existing jobs and the transparent lower surface does not claim the field.
5. **Visual invariant:** page size still represents only current PageRank. Curved arrows still mean directed relations, and dragging only changes screen position. Link weight and opacity represent recent flow, not PageRank score or a hidden edge weight.

### Bounded trial

- **Baseline:** `/page-rank/1`, preserved as a static-topology PageRank field.
- **Density:** `/2` begins with 150 pages and 725 directed links—about 2.45 times `/1`'s 296-link default—so link formation and retirement occur inside a substantially denser field. Those extra links never enter the spring layout: page positions retain the same two-link backbone used by `/1`, keeping its even spread instead of collapsing the dots into the centre.
- **Research adaptation:** Gross and Blasius describe adaptive networks as systems where state and topology coevolve; Barrat, Barthélemy, and Vespignani distinguish interaction strength from topology in weighted networks. This route applies the narrow, inspectable version: measured link flow feeds a slow link-replacement rule, while the PageRank transition remains unweighted. Sources: [Adaptive coevolutionary networks: a review](https://royalsocietypublishing.org/doi/10.1098/rsif.2008.0010); [The architecture of complex weighted networks](https://www.pnas.org/doi/10.1073/pnas.0400087101).
- **Invariants:** no self-link or duplicate directed link is created; total link count and each source page's outgoing-link count stay unchanged by a replacement; rank remains normalized in diffusion mode; random-surfers retain identity and colour; `/1` is not imported or changed by this trial.
- **Verification target:** deterministic tests exercise a 150-page baseline and verify that an adaptive update is reproducible, changes the requested number of endpoints, and preserves directed-link and outgoing-budget constraints.
- **Unresolved question:** compare this traffic-reinforced rule against a version where edge strength enters the transition probability itself; that would be a weighted PageRank experiment, not a visual variation of this one.
