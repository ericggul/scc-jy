# spoon-class

`/spoon-class/default` embeds one actual `dino.html` from [alexelzx/chrome-dino](https://github.com/alexelzx/chrome-dino), pinned to commit `6e472666cfd94e95056b7e747f46badf00e1226d`. `/spoon-class/1` is the responsive module-field fork. `/spoon-class/2` is its human-life visual fork: a pixel human begins at age `0`, low obstacles are tests, and tall obstacles are larger life blocks. `/spoon-class/3` is the high-density human-life wall. `/spoon-class` lists all variants.

## Baseline and ownership

The editable upstream HTML is stored byte-for-byte in `components/standalone/spoon-class/default/source/dino.html`, `1/source/dino.html` and `2/source/dino.html`. It includes the complete Runner, Trex, Horizon, Obstacle, DistanceMeter and GameOverPanel implementations, both sets of seven PNG sprites, three encoded sounds, and original document/CSS. Jump physics, rounding, spawn rules, collision boxes, sound decoding, score flashing, restart exceptions and the Chrome user-agent guard execute unchanged. The intro completion bridge is the explicit compatibility correction described below. Do not replace the engine with redrawn shapes, synthesized audio, rewritten physics, or constants from another Dino release.

The `default`, `1` and `2` `source/package-source.mjs` scripts package the HTML as `source/document.json` for a static import and add a Content Security Policy to disable external requests plus `compatibility.mjs` before the original bootstrap. `default` changes only the upper-right HUD into the age clock. `1` additionally sets a 150px tile viewport, removes the original prompt/share/non-Chrome notice DOM, and relays trusted player key events to its wall host. `2` retains that module surface and input relay, but replaces only the six Runner image resources for both pixel densities: T-Rex frames become a human, small cactus frames become test papers, and large cactus frames become life blocks. `3` reuses the packaged `2` game document without a second source copy. The bridge listens for standard `animationend` and completes the original 400ms intro by timer when no event arrives. Completion is idempotent so a late event cannot reset the runway or duplicate listeners. The original engine freezes world time while `playingIntro` is true; missing completion otherwise leaves cacti stationary indefinitely. The Runner engine, source styles and embedded media stay intact. Regenerate the matching variant with `node apps/scc/components/standalone/spoon-class/<variant>/source/package-source.mjs` after an intentional source change and document that change.

`default` renders one viewport-sized source iframe. `1` and `2` measure their own viewport, repeat only the needed number of 150px-high tiles, and remeasure on resize. `3` preserves the `2` source document at its native 600×150 canvas size, then scales the complete browsing context inside each tile: it selects 4×10 at normal desktop density, reaches 6×15 only when each game can remain at least 50% scale, and reduces the count on small displays before game pixels fall below 32% scale. Each source document has script and same-origin permissions, retaining normal document-origin semantics for the local trusted source. It preserves quirks mode, default browser styles, style-sheet indexing, global singleton, event targets and canvas coordinates independently of SCC's Tailwind reset. In all module variants, Space, Up, Down and Enter are forwarded from the host or any focused game tile to every game tile; their original Runner listeners perform the response. In `default`, `2` and `3`, the upper-right score is replaced by the pixel age clock `00Y 00M 00D`; it starts at birth and advances six months every second, with a 30-day interpolation within each month. `MONTHS_PER_SECOND` is the sole setting for future pacing changes. Removing a tile destroys its game document and its listeners, animation loop and audio context. The route and experiment registry remain thin. No dependencies or servers are added.

## Source and evidence

The upstream GPL-2.0 `LICENSE` is retained alongside the source, together with the Chromium copyright/BSD notices already embedded in the HTML. Preserve both. The [freeCodeCamp article](https://www.freecodecamp.org/news/how-the-chrome-dino-game-works/) is background reading; the pinned source defines this experiment's actual behavior.

2026-09-08 correction: the earlier hand-drawn renderer, synthesized cues and rewritten model were rejected for failing source fidelity and removed from this variant. The baseline is now the upstream game itself; the intervention is its isolated SCC host and restriction of unrelated external requests. Future experiments should fork this baseline into a new registered variant.

2026-09-08 verification: all 26 source tests (`default`: 8, `1`: 8, `2`: 10), scoped ESLint and the full SCC typecheck passed. The tests cover upstream byte comparison, packaged-source equality, inline JavaScript parsing, embedded asset integrity, the stationary-cactus failure when intro completion is withheld, fallback completion, differential runs against the unmodified source, the synchronized input relay, `2`'s six sprite substitutions and the shared six-month age clock.

Follow-up after the user reported stationary cacti: the original engine reproduced that state in a controlled Node clock when the animation completion event was withheld. With a matching source intro-end event, the hosted engine and the unmodified source were state-identical over 900 frames, including current speed, cumulative distance, T-Rex jump state, horizon offset, cloud state, obstacle type/size/position/gap/collision boxes, score flash, collision, restart and post-restart movement. The compatibility bridge also completed the original intro when no event arrived, then moved cacti toward the player. Duplicate completion did not reset the runway. Browser verification at the supplied local HTTPS route confirmed that `default` is one original game, `1` fills the viewport with modules, and host Space starts every visible module. `2` visibly renders the human, test and large-life-obstacle sprites; Space makes every visible human jump. Touch and audio paths remain unverified.
