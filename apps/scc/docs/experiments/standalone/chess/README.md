# Chess

Experimental standalone routes `/chess/1`–`/chess/4`, added 2026-09-08; `/chess` lists the variants. `/chess/1` is the fixed light baseline with staggered relation-edge draw. `/chess/2` is an isolated full copy of that baseline, prepared for a later visual study. `/chess/3` preserves `/chess/2`'s game model and controls in a twisted three-dimensional coordinate field: every original square retains its chess adjacency and relation endpoints while its visual point is mapped onto one continuous curved surface.

`/chess/4`, added 2026-09-09, repeats the `/chess/2` board as a responsive continuous field of independent simulations. The field derives its tile size and row/column count from the viewport, extends beyond an edge where required, and clips there so no outer whitespace or stronger board seam appears. Each board retains its own game, relation archive, timing and terminal restart. One right-side expand control applies pace, edge shape, text visibility, aggregate, and dark mode to every board. When aggregate is off, its per-board canvas work is skipped.

The participant watches an automatically restarting computer match. The board's own center is fixed at 50% of viewport width and height; controls are positioned separately and never shift it. Both variants retain monochrome movement surfaces with red reserved for hostile relations. There is no decorative title or persistent move panel. Move history is available on demand.

`/chess/1` side gutters derive their values from the current model state: move number and turn, that side's last SAN move, legal-move count, empty-square attack count, and the bounded chooser's next coordinate proposal and policy. `/chess/2` removes those gutters and places its collapsed parameter controls in the right-side margin, leaving the centered board geometry unchanged. `/chess/3` keeps those right-side controls while replacing the visible planar board with its spatial coordinate counterpart.

The first ivory/olive treatment and sidebar were rejected by the user on 2026-09-08. `/chess/2` and `/chess/3` use plain text controls in the right margin: cubic relations by default, visibility toggles for labels and piece text, aggregate mode, dark mode, and inline pace and size ranges. Pace sets the interval between moves (0.05–0.5 seconds; 0.1 seconds by default); size requests 40–90% of the viewport's smaller dimension, clamped to keep the board clear of controls. Reset starts a fresh automatically playing game.

The pure model owns legal moves, special moves, SAN notation, terminal states and a bounded two-ply computer chooser. Threefold repetition and the fifty-move rule end the simulation automatically rather than offering tournament claim procedures. The computer is a lightweight simulation opponent, not a rated chess engine.

`/chess/3` record, 2026-09-09: source baseline `/chess/2`; invariant: rules, semantic endpoints, pace, visibility options, and aggregate archive remain shared while only the coordinate presentation changes. The three-dimensional field uses one fixed continuous mapping, relation geometry is retained in static buffers for aggregate mode, and standard dark-mode hostile relations use strong red (`#ff1838`).

Validation: scoped ESLint and SCC TypeScript checks passed. Pure model tests cover ordinary and special moves and terminal states. An authorized HTTPS browser capture on 2026-09-09 confirmed that `/chess/3` renders its curved lattice and live relation geometry without a visible runtime error. The viewport centering and wrapping controls are CSS contracts, not recorded visual observations.
