# 2026-08-27 — 전시장 똥트맵: 3D 시각화 조사와 설계 결정

## 범위와 보존점

- 대상: 전시장 `/screen`의 기존 **현황**과 오른쪽 `오늘의 기록`은 유지한다.
- 변화: 기존 **랭킹**과 **지도**의 두 뷰를 하나의 3D **똥트맵**으로 대체한다.
- 사건: 서버가 확정해 보낸 `DdongMeongArchiveEntry` 한 건이다. 가상의 점·예시 데이터는 넣지 않는다.
- 데이터 계약: 오른쪽 `오늘의 기록`과 같은 브라우저 아카이브를 그대로 쓴다. 날짜·전시 기간으로 별도 필터하지 않는다.
- 용량: 브라우저 아카이브는 이미 최근 30일/최대 500건으로 제한된다. 3D 장면도 그 500개의 실제 사건까지만 그린다.

## 시각 언어

- **관찰자:** 전시장 스크린 앞의 방문자. 한 화면의 일은 현재 축적된 사적인 세션을 하나의 똥트맵으로 읽는 것이다.
- **표면:** 별도 캔버스 배경 없이 기존 전시장 배경 위에 좌표선은 거의 흰색, 실제 사건 모델만 밝은 토양색으로 둔다. 이 색은 상태 장식이 아니라 모델의 물질성이다.
- **서명 요소:** 실제 기록마다 놓이는 하나의 매끈한 나선형 3D 똥. 기술적 event display의 엄숙함과 가장 사적인 신체 사건의 충돌이 풍자의 작동점이다.
- **운동:** 카메라가 아주 느리게 궤도 이동하되, 관람자는 마우스 드래그로 즉시 각도를 바꾸고 휠로 거리를 바꿀 수 있다. 카메라 쇼·입자 폭발·글로우·가짜 라이브 지표는 쓰지 않는다.
- **레이블:** 마우스가 사건 가까이에 오거나 회전 중 전면 중앙에 가장 가까운 사건 하나만, 시간·체류시간·콘텐츠·닉네임을 표시한다. 전체 레이블은 금지한다.

## 자기비평과 설계 확정

이 장면이 흔한 ‘검은 배경 + 네온 데이터 대시보드’가 되지 않도록, 차트 카드·게이지·상태 배지·수치 타일은 만들지 않는다. 검은 장면은 Ryoji Ikeda의 표면을 흉내 내기 위한 것이 아니라, 3개의 실제 척도와 3D 물질의 깊이를 동시에 보이게 하기 위한 관측 조건이다. 유머는 갈색 이모지를 반복하는 데 있지 않고, 정교한 과학 event display가 화장실 체류 기록을 과잉-정밀하게 대우한다는 불균형에서 나온다.

## 구현 단위

`components/screen/event-field/`에 데이터 투영, Three.js 장면, HTML 레이블을 분리한다. `InstancedMesh`로 동일한 정교한 나선형 모델을 최대 500회 그려, 사건 ID와 인스턴스 ID를 안정적으로 매핑한다. `OrbitControls`는 드래그 궤도 이동·휠 줌을 담당한다. 외곽 프레임·바닥·색면·임의 격자는 없고, 명확한 X/Y/Z 기준축만 둔다. 각 사건에서는 X·Y·Z 방향으로 세 개의 수선을 각 좌표면까지 그려 좌표를 판독한다. 축 이름은 실제 각 축 곁의 작은 Three.js 레이블만 쓴다. 서버는 기존의 추상 기록만 계속 제공하고, 색·회전·라벨 위치 같은 표현 상태는 브라우저가 계산한다.
